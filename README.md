# ONE TAP — Roblox Shooter

Classic Roblox-style multiplayer shooter prototype.

## Included in this first version
- One Tap mode: any valid hit kills.
- Server-authoritative raycast validation.
- Basic Rifle tool.
- Simple HUD with crosshair and ammo.
- Starter city block generated by script.
- Project structure ready for Rojo.
- Server-owned TDM / FFA rounds, scoring, team assignment and spawn protection.
- Server-owned magazines and reloads; equipped Rifle required to fire.

## Roblox Studio setup
1. Install Rojo (optional but recommended).
2. Run `rojo serve default.project.json` and connect the Studio Rojo plugin.
3. Press Play with 2+ players for multiplayer testing.

## Controls
- Left mouse: fire
- R: reload

## Match modes

`src/ReplicatedStorage/MatchConfig.lua` configures rotation, minimum players,
round time, intermission, results time, score limits and spawn protection.
Default rotation: TDM then FFA; 2 players minimum; 5 minute rounds;
TDM first to 50 team kills, FFA first to 25 personal kills.
Use `Rotation = {"TDM"}` or `{"FFA"}` for a single mode.

- TDM assigns Red/Blue teams evenly at round start and assigns late joiners
  to the smaller team. Friendly fire is disabled. Teams stay fixed during
  a round; the next round rebalances the roster.
- FFA clears teams and allows every other player to be attacked.
- Kills and deaths reset each round. Suicides/environmental deaths grant no
  kill. Departed players retain their FFA score until round reset, including
  reconnects. FFA results show the winner's UserId; ties/no kills show Draw.
- The server ends rounds on score limit, timeout or insufficient players.
  Damage is disabled while waiting, preparing, between rounds and in results.
- MatchService owns dedicated spawns and assigns RespawnLocation. Roblox
  auto-respawn remains enabled; ForceFields protect fresh spawns for 3 seconds.
- One Tap remains lethal on any accepted hit. Server raycasts, finite vector
  checks, range, origin proximity/visibility, fire rate, alive/equipped checks,
  ammo and team rules all run before damage. Client sends only aim vectors.
  Ammo HUD reads server attributes; R requests a server-timed reload.

## Source layout / Rojo

- ReplicatedStorage: WeaponConfig, MatchConfig and runtime match attributes.
- ServerScriptService: CityGenerator, GameServer, MatchService and pure MatchRules.
- StarterPack/Rifle: Gun client and `init.meta.json` (Rojo Tool metadata).
- StarterPlayerScripts: crosshair, ammo, mode, phase, timer and score HUD.

The original `Tool.meta.json` is renamed to Rojo's directory metadata
`init.meta.json` so Rifle syncs as a Tool rather than a Folder.
Build with `rojo build default.project.json -o OneTap.rbxlx`.

## Validation

Run `python3 tests/run_tests.py` on Linux with liblua5.4 installed for Lua syntax,
pure mode-rule tests, and mocked server combat/round lifecycle integration tests.
Roblox Studio multiplayer checks are still required:

1. Start Server with 2–4 clients; verify balanced TDM teams and separate spawns.
2. Hit a teammate (no damage/score); hit an enemy after protection expires
   (one kill, one death, one team point); confirm repeated hits cannot double count.
3. Temporarily use a score limit of 1; verify results freeze combat, round
   reset clears stats, FFA clears teams, and FFA kills credit only the attacker.
4. Use short timers; verify timeout ties, no-kill Draw, late joins, disconnects
   below MinPlayers, automatic respawn and score persistence on reconnect.
5. Fire unequipped/dead, spam shots/reloads, and send zero/NaN/infinite aim
   vectors; verify no invalid damage. Verify no damage through walls or ForceFields.
6. Build/sync via Rojo and confirm Rifle is a Tool with Gun as LocalScript.
